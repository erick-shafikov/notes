# Классы сложности P и NP

Сложность алгоритма описывает расход ресурсов при росте **длины входа**. Классы `P` и `NP` классифицируют задачи принятия решения — задачи с ответом «да» или «нет», например: «существует ли маршрут длиной не более K?».

## P: полиномиальное решение

`P` — задачи, которые детерминированный алгоритм решает за полиномиальное время относительно длины входа: `O(n)`, `O(n log n)`, `O(n³)` и т. п. Полиномиальность означает существование некоторой постоянной степени, а не обязательно практическую быстроту.

Пример: достижима ли вершина `t` из вершины `s` в графе? Обход BFS/DFS решает это за `O(V + E)` при списках смежности. Сортировка — задача получения результата, поэтому формально её обычно не называют языком из P; можно рассмотреть связанную задачу решения, например «упорядочен ли массив?».

## NP: полиномиальная проверка сертификата

`NP` — задачи решения, у которых для ответа «да» существует сертификат полиномиальной длины, проверяемый детерминированно за полиномиальное время. Эквивалентное определение — решение на недетерминированной машине за полиномиальное время.

Для любого входа с ответом «нет» проверяющий алгоритм обязан отклонять **все** сертификаты. Из определения NP не следует, что ответы «нет» также имеют короткие проверяемые сертификаты: это связано с классом `coNP`.

`NP` означает nondeterministic polynomial time, а не «неполиномиальные задачи». Всегда `P ⊆ NP`: если можно быстро решить задачу, можно проверить её, не используя сертификат. Равны ли P и NP — открытый вопрос. [Clay Mathematics Institute](https://www.claymath.org/millennium/p-vs-np/)

## Пример сертификата: сумма подмножества (Subset Sum)

Задача: существует ли подмножество заданных неотрицательных целых чисел с суммой `target`? Сертификат — индексы выбранных элементов. Повторять индекс нельзя, но два разных элемента с одинаковым значением использовать можно.

```ts
function verifySubsetSum(
  values: readonly bigint[],
  target: bigint,
  indices: readonly number[],
): boolean {
  if (target < 0n || values.some(value => value < 0n)) return false;
  if (indices.length > values.length) return false;
  const used = new Set<number>();
  let sum = 0n;
  for (const index of indices) {
    if (!Number.isInteger(index) || index < 0 || index >= values.length || used.has(index)) {
      return false;
    }
    used.add(index);
    sum += values[index];
  }
  return sum === target;
}

console.log(verifySubsetSum([3n, 7n, 10n], 13n, [0, 2])); // true
console.log(verifySubsetSum([3n, 7n, 10n], 6n, [0, 0])); // false: повтор индекса.
console.log(verifySubsetSum([], 0n, [])); // true
```

Код требует TypeScript с target ES2020 или новее из-за `bigint`. Проверка не ищет подмножество: она проверяет уже предложенное. Здесь `O(n + k)` операций над элементами и `O(k)` памяти для множества индексов, где `k` — длина сертификата. В битовой модели сложность сложения `bigint` зависит от длины числа; проверка всё равно полиномиальна по размеру входа и сертификата.

Полный перебор рассматривает `2ⁿ` подмножеств (простой пересчёт суммы каждого требует `O(n · 2ⁿ)` операций). Наличие такого перебора не доказывает отсутствие более быстрого алгоритма.

## NP-трудность, NP-полнота и сведение

Полиномиальное сведение `A ≤p B` преобразует каждый вход задачи A во вход B за полиномиальное время, сохраняя ответ «да/нет». Если умеем быстро решать B, то умеем быстро решать A.

| Класс | Условие | Пример |
| --- | --- | --- |
| P | полиномиальное решение | достижимость в графе |
| NP | полиномиальная проверка сертификата для «да» | SAT, а также все задачи P |
| NP-трудные | любая задача NP сводится к ним | оптимизационная задача коммивояжёра |
| NP-полные | одновременно в NP и NP-трудные | SAT, 3-SAT, Subset Sum |

NP-трудная задача не обязана принадлежать NP и даже не обязана быть задачей решения. Для доказательства NP-полноты новой задачи B нужно показать `B ∈ NP` и свести **известную NP-полную A к B**. Обратное направление не доказывает трудность B.

Если хотя бы одна NP-полная задача имеет полиномиальный алгоритм, то `P = NP`. Пока неизвестно, существует ли такой алгоритм; нельзя утверждать, что всем NP-полным задачам доказанно требуется экспоненциальное время.

## Почему размер чисел важен

Число `W` в двоичной записи занимает `Θ(log(W + 1))` бит. Динамическое программирование для Subset Sum за `O(nW)` при неотрицательных числах и цели `W` — **псевдополиномиальный** алгоритм: полиномиальный по значению W, но не по длине его двоичной записи. Поэтому он не доказывает `P = NP`.

Практически NP-полные задачи решают полным перебором с отсечениями, динамическим программированием для небольших параметров, SAT/ILP-решателями или, для подходящих оптимизационных задач, приближёнными методами. Хорошая работа на конкретных входах не означает полиномиальной гарантии для всех входов.
