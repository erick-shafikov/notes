# Автоматы и конечные автоматы

Автомат — математическая модель системы, которая читает вход и меняет состояние по правилам перехода. Состояние хранит существенную информацию о прошлом. Конечный автомат имеет конечное число состояний: он не располагает неограниченным стеком или лентой памяти.

Примеры: проверка формата токена, протокол соединения, состояния интерфейса, поиск строк. Автомат-распознаватель после чтения слова отвечает, принадлежит ли оно заданному языку; автоматы Мили и Мура также выдают выходные значения.

## Детерминированный конечный автомат (ДКА, DFA)

Задаётся пятёркой `M = (Q, Σ, δ, q₀, F)`:

- `Q` — конечное множество состояний.
- `Σ` — конечный входной алфавит.
- `δ: Q × Σ → Q` — функция перехода.
- `q₀ ∈ Q` — начальное состояние.
- `F ⊆ Q` — принимающие состояния.

На каждую пару «состояние, символ» приходится ровно один переход. В полной модели отсутствующие переходы направляют в поглощающее состояние отказа. Слово принимается, если после чтения **всего** слова автомат находится в `F`. Пустое слово принимается тогда и только тогда, когда `q₀ ∈ F`.

## Пример: двоичные строки с чётным числом единиц

Нужно запомнить только чётность. Ноль её сохраняет, единица переключает.

| Состояние | Вход 0 | Вход 1 | Принимающее |
| --- | --- | --- | --- |
| even (начальное) | even | odd | да |
| odd | odd | even | нет |

```ts
type State = "even" | "odd";
type Bit = "0" | "1";

const transitions: Record<State, Record<Bit, State>> = {
  even: { "0": "even", "1": "odd" },
  odd: { "0": "odd", "1": "even" },
};

function acceptsEvenOnes(input: string): boolean {
  let state: State = "even";
  for (const char of input) {
    if (char !== "0" && char !== "1") return false;
    state = transitions[state][char];
  }
  return state === "even";
}

console.log(acceptsEvenOnes("101")); // true: even → odd → odd → even
console.log(acceptsEvenOnes("111")); // false
console.log(acceptsEvenOnes("")); // true: ноль единиц — чётное число.
console.log(acceptsEvenOnes("10x")); // false: символ вне алфавита.
```

Для фиксированного автомата обработка строки длины `n` занимает `O(n)` времени и `O(1)` дополнительной памяти. При переменном размере автомата таблица переходов занимает `O(|Q| · |Σ|)`.

## Недетерминированный конечный автомат (НКА, NFA)

У пары «состояние, символ» может быть несколько следующих состояний или ни одного. В ε-НКА разрешены переходы без чтения символа. Слово принимается, если **существует** путь, который прочитал всё слово и завершился в принимающем состоянии.

При моделировании храним множество активных состояний. Перед чтением и после каждого шага для ε-НКА добавляем состояния, достижимые по ε-переходам (ε-замыкание). Например, для языка строк, оканчивающихся на `01`, НКА может в начальном состоянии читать любой префикс и на очередном `0` дополнительно начать ветку проверки окончания `01`.

Любой НКА преобразуется в ДКА методом подмножеств: состоянием ДКА становится множество состояний НКА. В худшем случае из `q` состояний получается до `2^q`. НКА и ДКА распознают один и тот же класс регулярных языков; недетерминизм может дать более компактное описание, но не более мощный язык.

## Другие модели и ограничения

| Модель | Память / выход | Пример |
| --- | --- | --- |
| ДКА / НКА | конечное состояние | идентификаторы, двоичная чётность |
| Автомат Мура | выход зависит от состояния | индикатор текущего режима |
| Автомат Мили | выход зависит от состояния и входа | реакция контроллера на событие |
| Магазинный автомат | дополнительный стек | произвольная вложенность скобок |
| Машина Тьюринга | неограниченная лента | общая модель вычислений |

Конечный автомат не распознаёт язык `aⁿbⁿ` для произвольного `n`: требуется неограниченно помнить число `a`. Аналогично нельзя проверить произвольную глубину скобок одним конечным набором состояний. При заранее ограниченной глубине конечный автомат возможен.

Классические регулярные выражения эквивалентны конечным автоматам. Возможности библиотечных regex вроде обратных ссылок выходят за рамки классической модели. Минимизация ДКА объединяет состояния с одинаковым поведением на всех продолжениях; сначала удаляют недостижимые состояния, затем уточняют разбиение принимающих и непринимающих.

[Ахо — Корасик](methods/sorting/aho-corasick.md) использует состояния-префиксы и суффиксные ссылки для поиска множества слов. Его удобно понимать как конечный автомат с выдачей найденных образцов.
